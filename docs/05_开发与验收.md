## 2. 实际执行环境与限制

2026-09-12 本地检查使用 Windows、Node.js 24.16.0、Python 3.12.10；SQL 检查所用 SQLite 版本记录在 `tests/results/schema.json`。这些是开发与设计验证环境，不是已经批准的生产运行时。

浏览器使用 Chromium 加载本包提供的 HTML 文本。检查通过 `page.set_content` 提供页面，并注入仅限测试的 localStorage 替身；没有执行本地文件导航或改变浏览器管理策略。检查能够验证 DOM 动作、同一份状态、序列化内容和新文档重新初始化，但**没有验证用户浏览器原生 file:// 存储、真实浏览器重启、微信本地存储或跨设备同步**。截图来自这个渲染环境，不是微信真机截图。

23 项浏览器检查没有捕获到 JavaScript 页面异常。提交超时、并发认领和网络恢复为明确的演示场景；SQL 检查中的两个连接确实同时对临时 SQLite 文件发起认领竞争，该证据不能扩大为实际 API 的并发测试。

生产 SQLite 要求不低于 3.51.3，并在构建记录中保存 `SELECT sqlite_version()` 的真实返回值、驱动版本和镜像 digest；这是本项目选择的最低门槛，不是“最新版本”的声明。SQLite 官方 WAL 文档说明了多连接写入/检查点的运行条件及版本要求。[T08] 本地 DDL/事务用例通过不构成生产运行库、运行时安全或长期可靠性认证。

`tests/deployment_test.py` 使用 PyYAML 6.0.3 解析生产 Compose 模板，读取备份 JSON 契约，并调用本机 Node Intl 验证显式北京时间计算。Linux 环境还应使用 systemd-analyze 验证每日北京时间 04:00 的日历表达式；当前 Windows 运行跳过该项。

`tests/docker_smoke.py` 单独检查开发容器：已执行开发 Compose 配置解析与镜像构建，在 Docker Engine 29.0.1 / Compose 2.40.3 的 Linux amd64 引擎中以临时项目运行 HTTP 初始化、原图上传和容器重建后的持久化检查。采用 UID/GID 10001、只读根文件系统与本机端口绑定。该结果不是独立目标 Linux 主机安装、来源网络隔离、微信真机、停服备份、恢复或媒体清理验收。检查只清理自己创建的临时项目和卷。

## 4. 必须覆盖的真实服务验收

### 家庭、权限与资料

初始化的重复请求及并发请求不会产生两个家庭；每个可变资源按实例、数据代次和实体 ID 处理。规范名按产品要求完成 Unicode NFKC 与完整大小写折叠，包含中文、组合字符和非 ASCII 大小写样例；原型的小写比较不充当完整实现。

停用成员同时检查全日期自己的待做、自己正在做、自己发起的活跃投票和最后启用成员；与新增点菜/认领在事务上串行。停用成员只能核对自己已经存在的成功回执，不获得新的业务写权限。菜品/分类停用不会删除历史资料。

菜谱文字与步骤附图整批保存，过期 revision 不覆盖新内容，失败不丢本机输入。旧菜单显示原菜名、分类、封面和点菜人快照，做法明确展示当前菜谱。输入内容按纯文本输出，不能执行标签或脚本。

### 点菜、状态、时间与统计

同一菜选择两次保留两个条目及备注。批次中任一菜不可点时整批不落库；同一 Key 同一载荷返回原 ID，不同载荷明确冲突；成功回执不能因 TTL 到期丢失后重复创建。

在请求发送前模拟本地凭据持久化失败，必须不发送；分别在事务前、提交后、响应中断时重试。读取不到回执不等于可以改 Key。成员切换后迟到响应不得覆盖另一人的草稿。

覆盖北京时间 23:59 首次成功、次日重放、次日才首次执行旧目标日期；覆盖 UTC 15:59:59.999 / 16:00:00 两侧，以及主机默认时区不同但家庭日期仍保持北京时间。04:00 只触发维护，不改变菜单日界线；没有业务时区切换功能。服务器日期为权威，手机时钟不能改变菜单日期。恢复后代次变化隔离旧意图，不自动补送。

至少两台客户端同时认领同一条目，仅一方成功；取消、取消认领、完成与评价各自遵守权限和终态规则。往日未完成保持原日期。取消不参与有效进度、日均分和菜品评分；没有评价的完成菜不以零分拉低平均分。日均分与菜品平均分使用产品文档定义的不同权重。

### 投票与历史

同一时间最多一轮活跃投票；每位成员可以选择零道、一道或多道候选，也可在结束前增选、取消或替换选择。同一成员对同一候选最多计一票，投票人数按至少选择一道菜的成员去重，多选不增加参与人数。候选属于本轮；并列和零票结束要求发起人明确选择；结束与最后一次选择变更按照事务最终状态判定。

同一成员、同一菜品、同一菜单业务日期最多一份有效评价；同日重复点菜共享这份评价，提交后不可编辑或覆盖。下一业务日期存在该菜的完成事项时可再次评价。升级旧数据时不得删除冲突评价，最早记录作为有效日评，其余保留为不参与展示和计分的迁移旧记录。

历史是按北京时间业务日期自动派生的终态归档：往日完成和取消事项按原日期出现；往日待做和正在做事项继续作为超期事项处理，只有进入完成或取消后才归档。没有手动归档操作。

结束后可由首页再次进入最近结果。取消不生成获胜菜。获胜菜一次加入菜单之后即使菜单被取消，也不允许再次加入；调用返回实际条目和日期。下架候选仍可保留结果，不能绕过可点状态创建菜单。历史复点按原条目选择，不以菜名去重。

### 图片与文件

使用真实检测器支持样本，而不是任意 MIME/扩展名名单。空文件、超限、伪造类型、截断、损坏、无法识别内容和主动内容均有明确结果。对允许保存但不可预览的格式显示占位和真实取回途径。SVG 等主动内容不作为同源可执行页面打开。[T07]

验证 52,428,800 字节边界与边界加一，断网/取消/磁盘满/进程退出后没有可引用半文件；正式文件 SHA-256 与上传原字节一致。封面与步骤图都必须验证保存、替换、预览失败及下载。大文件不全量装入进程内存；自动预览大小策略不改变接收原文件上限。

检测器识别、实际解码与微信是否支持展示是三个不同结论。图片原文件可能含位置等元信息，界面在保存前提示；原图要求不自动剥离元信息。

### Linux 与数据运维

验证实际内网绑定、允许来源网络和非允许网络，不能只读 Compose 配置。Docker published port 与主机防火墙行为以实际 Engine/防火墙后端验收。[T05][T06]

在 linux/amd64 的正式镜像运行服务、执行最小业务与原图上传，再重建容器检查持久化。检查只读文件系统、UID/GID、缺失挂载、存储不足、请求限制与日志保留。

备份数据库与媒体清单相符，并核对所有散列；损坏包、危险 TAR 条目、超限解包、跨文件系统候选目录和不兼容 schema 一律拒绝。恢复阶段注入进程中断，重启后按维护阶段记录判断继续/回退，不把不完整候选当现用数据。恢复成功后实例与数据代次符合协议，原图无缺失。备份失败不清理仅存的成功备份。

完成正常停服、异常终止与设备断电后的检查；这需要真实环境，不以 `synchronous=FULL` 参数或完整性检查单独替代。外接介质备份需要实际复制和抽样恢复，不能把同一块盘内另一目录当作故障隔离。

备份调度按真实主机验证每天北京时间 04:00，主机默认时区为 UTC 时也不能偏移。分别验证关机错过、休眠恢复、锁被占用、04:15 之后的自动调用、原服务已被手动停止、时钟不可信和容量不足；自动任务不得在白天补做停服或擅自启动服务。

分别注入归档失败、归档已成功但服务无法恢复、原数据不安全三种结果；日志区分归档与服务恢复，失败不删除成功包。构造超过 10 份成功备份以及 `.partial`，核对只在归档和健康恢复均成功后清理最旧成功包。每周异介质副本核对全部清单散列并记录实际介质身份，不把本机日志成功当作副本完成。
