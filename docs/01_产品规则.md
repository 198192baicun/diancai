# 产品规则

## 1. 定位和边界

一户家庭、一份公共菜品库、按日期组织的菜单。客户端是原生微信小程序，iOS 与 Android 使用同一业务设计。主流程：选择成员 → 选菜 → 提交 → 认领 → 查看做法 → 完成 → 评价 → 历史。辅助流程为轻量投票。

没有注册、密码、OpenID 或个人私有菜品。成员可在“我的”主动选择微信头像或上传图片；头像只用于展示，不参与认证。所有启用成员是同一种业务角色；成员选择用于记录操作者，不是身份认证。家庭局域网被视为可信，具备访问能力的人能够冒用成员，此风险必须写在接入说明中。

首期没有多家庭、商城、支付、采购库存、营养计算、AI 推荐、消息推送、云同步、网页运维台、在线数据库切换和通用权限平台。工程只维护 Linux + Docker Compose 一种服务交付路线。

服务必须检查请求 Host；直接开发启动默认只接受本机地址，家庭 LAN 接入须明确配置实际地址与端口。不带 Origin 的原生微信请求可用，携带 Origin 的请求须匹配明确允许的来源，空来源白名单不放行浏览器来源。该检查不替代家庭网络隔离或身份认证。

## 2. 初始化、成员和分类

首次初始化在一个事务内创建家庭名、固定业务时区 `Asia/Shanghai`、初始成员及六个分类：荤菜、素菜、汤、主食、凉菜、其他。家庭设置只有一条记录。并发初始化只能成功一次。未初始化只开放健康、服务识别、初始化接口；不能用初始化接口覆盖已有家庭。

成员、分类、菜名使用去除首尾空白 + NFKC + Unicode case-fold 的规范键判重；JavaScript 实现须有固定版本的 case-fold 规则，不能把 `toLowerCase()` 称为完整 Unicode case-fold。界面保留规范化后的显示名。停用实体仍占用名称；重新启用同一实体不会创建替身。

成员只启用/停用，不物理删除。停用保护覆盖所有日期：最后一个启用成员、自己点的待做事项、自己正在做的事项、自己发起的进行中投票都会阻止停用。返回依赖数量与可跳转条目。待做先取消或完成认领；正在做先完成、取消认领或取消；投票先结束或取消。已投票的普通成员可以停用，其已投票保留。允许停用自己，成功后当前设备退出成员选择。

分类只启用/停用，不物理删除；仍有上架菜品时不可停用。停用分类下的下架菜仍可编辑和查看，但上架前必须选择启用分类。

## 3. 公共菜品和菜谱

启用成员均可新增、编辑、上架、下架公共菜品。创建人只表示来源，不产生所有权。日常不提供物理删除。下架不影响已点菜、正在做、评价和历史查看；下架菜不可新点或历史复点。

进行中投票的候选菜不能下架。结束后允许下架；若获胜菜已下架，结果仍可看，加入菜单时解释不可用原因。解除下架后若本轮从未加入过，可执行一次加入。

资料包含名称、分类、可空时长、简介、可选介绍语音、可空封面和有序菜谱步骤。允许没有图片/没有菜谱。一步可以附一张图片，不要求每步都有图片。菜品保存与步骤替换是一个事务；使用整数 `revision` 进行乐观并发校验。过期版本不能覆盖别人已保存的内容，返回当前版本，保留本机未保存内容供对照，不提供静默强制覆盖按钮。

菜单条目固定创建时的菜名、分类名、封面和点菜人名；认领时固定做菜人名。菜谱读取当前菜品资料，不建设菜谱版本历史。做菜页在一次浏览中保持所载入步骤稳定，用户刷新后说明资料读取时点。

## 4. 点菜与批次

加号只加入本成员、本服务、本数据代次的本机草稿。相同菜可重复添加，每次形成独立条目，备注互相独立，不按菜名合并。一次最多 50 条，单备注最多 200 字。未提交草稿可本机保存；不进行离线自动提交，不建设共享草稿。

提交冻结目标业务日期、操作者、幂等 Key 和原始载荷。保存待确认凭据成功后才发送网络请求。服务器使用事务保证批次全有或全无；任一道菜无效时返回所有失效项，不静默跳过。成功回执与菜单条目同事务提交。

没有收到响应叫“提交结果尚未确认”，不叫“提交失败”。结果未知时不能改原载荷换 Key。重新打开、切换成员或重连后可以查原请求回执；查无回执也不证明先前请求绝不会到达，只允许使用同 Key 重试，不允许直接放弃为一个新提交。业务日期已过且无成功回执时，先取得服务端的确定拒绝，再让用户确认新日期和新意图。

只有点菜人能编辑自己待做事项的备注。备注修改不影响创建日期、快照或其他重复条目。

## 5. 菜单状态与权限

| 原状态 | 动作 | 操作者 | 结果 |
|---|---|---|---|
| 待做 pending | 我要做 | 任意启用成员 | cooking，记录做菜人和认领时间 |
| 待做 pending | 修改备注 | 点菜人 | pending |
| 待做 pending | 取消这次点菜 | 点菜人 | cancelled，保留取消人/原因/时间 |
| 正在做 cooking | 取消认领 | 当前做菜人 | pending，清空当前做菜人和认领时间 |
| 正在做 cooking | 做好了 | 当前做菜人 | completed，二次确认，记录完成时间、可选成品照片及留言 |
| 正在做 cooking | 不做了 | 当前做菜人 | cancelled，保留当时做菜人、取消人/原因/时间 |
| 已完成 completed | 提交当日菜品评价 | 当天尚未评价过该菜的任意启用成员 | 状态不变；提交后不可修改 |
| 已取消 cancelled | 查看、另行点一次 | 任意启用成员 | 原记录不变；另行点菜走新批次 |

completed 与 cancelled 都是终态。不存在条目物理删除、终态回退、自动恢复、自动取消和自动转入今日。取消理由可空，最多 200 字。“取消认领”表示等待别人接手，“不做了”表示这一次结束，文案与按钮位置要区分。

认领、取消、备注编辑等全部带当前 `revision`，在写事务里校验启用成员和状态。条件不符返回最新条目；网络超时后先读状态判断是否已完成意图。原批次回执重放只返回原条目 ID，不把终态重置成待做。

## 6. 日期和统计

业务日期统一采用 `Asia/Shanghai`（北京时间），日界线为北京时间 00:00；审计时间采用 UTC。禁止依赖宿主机或容器的隐式默认时区，禁止客户端自行认定服务日期。初始化由服务端固定写入该时区；初始化页与设置页只读展示，不提供时区选择或修改入口。每天 04:00 是维护时间，不改变业务日期，也不触发未完成事项取消。

往日未完成在首页有独立入口，显示原日期，可继续认领、做菜、完成和取消。对往日记录的操作只改变该条目状态，不创建今日副本。历史归档是 `menu_item.menu_date < today AND status IN ('completed','cancelled')` 的查询，不单独建历史表或午夜搬运任务。往日 pending/cooking 不进入历史归档，继续出现在“往日未完成”；它们完成或取消后立即按原菜单日期进入历史归档。

今日数量只计 `menu_date=today`。概览分别显示待做、正在做、已完成；已取消独立展示，不计入进度分母。无有效事项显示未点菜。进度为已完成数 / 非取消总数；分母为零时不显示百分比。

菜品均分为该菜所有有效每日评价的算术平均；菜单日均分为该菜单日期全部有效每日评价的算术平均。同日重复点同一道菜不会重复增加评价权重。没有评价显示“未评价”，不是 0 分。展示保留一位小数，存储与计算保留原始数值。

## 7. 评价和历史复点

评分只能为 1—5 整数，正文可空、最多 1000 字。评价按成员、菜品和菜单业务日期唯一：同一成员对同一道菜在同一菜单日期只能提交一次；同日重复点了多份该菜也只产生一份当日评价。提交后不可编辑、覆盖或再次提交。下一业务日期存在该菜的 completed 事项时，可以为新的菜单日期再次评价。历史 completed 仍可补交尚未提交的当日评价；成员停用不能新增评价，已留下的评价仍计分。

历史详情显示快照；同菜多条各自保留。复点时逐条选择，默认继承备注，允许明确清空；失效菜显示原因并禁止选中。将选中条目加入当前成员草稿，经确认页提交，服务端同时保存来源条目 ID，创建今日快照与新点菜人。新条目不继承原做菜人、评价或状态。

## 8. 轻量投票

同时最多一轮 active。任意启用成员可发起，候选 2—10 道不同且上架、分类启用的菜。发起时保存候选菜名与图片快照。每成员可选择一道或多道候选菜；同一成员对同一候选最多记一票，结束前可增选、取消或修改。所有人可看票数。参与人数按至少选择一道候选的成员去重计算，不等于家庭启用人数；已投票成员停用后票数保留。

所有当前启用成员均至少选择一道菜时，服务端在最后一票事务中自动停止收票；唯一最高票直接结束并获胜，并列时保留 active 与 votingClosedAt，禁止任何改票，由发起人从并列最高中选定后结束。成员启停也在同一写事务中检查是否收齐，停收后不会因新增或启用成员重新开放。已停用成员的历史票继续参与计票。发起人仍可提前结束或取消；提前结束时唯一最高自动获胜，并列由发起人选择，0 票时所有候选并列。结束计票与 ballot 写入必须串行事务，不能先读取票数再无条件结束。取消不产生获胜者。

首页保留当前投票与最近结果；“我的 → 历次投票”及投票详情提供全部轮次历史，包括进行中、待裁决、已结束、已取消。按发起时间倒序，每页 10 轮，滑到底继续加载。停收或结束后公示每位参与成员姓名、选中菜品、备注和语音；进行中展示票数及自己的选择。每次提交保存成员姓名快照，后续公共改名不覆盖。投票备注最多 200 字，可附一条语音。

结束后任意启用成员可将可用的获胜菜加入今日菜单。每轮最多创建一个菜单条目；并发按钮、重试、菜单条目被取消都不会再次解锁。本轮结果展示实际加入日期和条目当前状态。获胜菜下架或分类不可用时仍允许看结果，但不能加入。

## 9. 输入与可用性

家庭名 1—30 字；成员/分类名 1—20 字；菜名/投票标题 1—50 字；简介 0—1000 字；备注/取消原因 0—200 字；评价 0—1000 字；步骤正文 1—2000 字，最多 50 步；可选预计时长为 1—1440 分钟整数。长度按 Unicode 码点计数，不按 UTF-16 代码单元计数。空白名称不合法。

图片上限沿用 52,428,800 字节，上传界面明确“单文件上限 50 MiB（约 52.4 MB）”。原文件按字节保存，无服务端压缩、转码或元数据清除。识别、预览和原文件取回是三个独立能力，详见运维与文件规范。


## 10. 我的待做与菜谱编辑草稿

“我的待做”仅列出当前成员已认领且状态为 cooking 的事项，覆盖所有日期，按原菜单日期从早到晚显示。完成、取消认领或取消后移出本列表，不改变原日期或创建副本。尚未认领的事项仍在公共菜单中选择。

菜谱编辑草稿仅保存在本机，按服务地址、实例、数据代次、成员与菜品 ID 隔离。每个已有菜品保留一份编辑草稿，并保留一份新菜草稿；编辑文字、步骤顺序和图片引用时同步保存。图片字节保存在家庭服务，本机草稿只保存图片引用及元信息，不将临时预览路径当作永久文件。存储失败显示明确提示；保存家庭菜谱成功后移除对应草稿。恢复、成员切换、服务切换不会自动重送旧草稿。

草稿列表允许删除新菜或已有菜品的本机编辑草稿，须二次确认；仅移除当前作用域的所选草稿，不修改公共菜品、历史或服务端媒体文件。取消时保留草稿，存储删除失败时提示重试，确认期间切换成员或家庭上下文后不执行删除。删除成功后刷新列表。此操作不涉及点菜草稿和待确认提交意图。

草稿保留编辑时 revision。当前菜谱已更新时，展示本机与最新资料的差异，逐项选择保留哪份内容后继续编辑；最终保存仍检查最新 revision，不提供绕过版本检查的覆盖入口。

## 11. 图文教程导入

导入先生成当前成员本机的新菜草稿，用户核对分类和内容后通过普通菜品保存流程写入公共菜品库，不直接创建菜单事项。导入成功前不替换已有草稿；已有新菜草稿时须确认替换。来源作者和链接保留在简介，正文按原顺序分段，图片按平台或用户所选顺序保存。图中的文字不进行识别或推测。

自动读取仅支持能够公开返回完整图文数据的小红书页面。分享输入仅接受一个小红书 HTTPS 链接，不兼容抖音；不能读取的页面明确返回不可用，并提供用户自行保存图片后的导入方式。当前不提供账号登录、验证码处理或浏览器脚本执行，也不承诺任意平台链接均能一键读取。

平台配图按平台提供的文件字节保存，不作二次压缩或转码；它可能已经由平台处理，不能宣称是作者上传前的原始文件。单图上限仍为 52,428,800 字节，自动导入整篇上限 200 MiB，正文段落和图片合计不超过 50 段，不静默截掉超限内容。导入失败不创建菜品；已完整接收的无引用文件只按停服维护规则清理。

## 12. 照片、语音与历史展示

完成前当前做菜人可选择最多 9 张成品原图、200 字心得和一条语音；最终确认与状态完成在同一事务保存。失败不产生部分完成记录，结果未知先读取事项，不自动补送照片。完成照片归属菜单事项，历史保留当次照片、原菜单日期、做菜人、完成时刻、备注、留言、有效评价和取消信息，不修改公共封面。

语音支持菜品介绍、点菜草稿备注、待做备注、认领留言、完成留言、评价和投票备注。每处一条、客户端录音最长 60 秒、MP3 原字节上传；文字可同时填写。录音与上传时禁止相关提交，失败保留文字并允许重录；未提交可播放、重录、移除。评价提交后语音与正文一起不可修改；公共菜品介绍语音随 revision 校验。取消认领清空当前认领语音。语音不做自动转写。

所有可预览图片支持点击放大，包括菜品封面、列表缩略图、步骤、编辑和导入预览、头像、完成照片及历史照片；不可预览原文件保留取回能力。评价明确区分菜单日期与实际评价时刻，以北京时间展示到分钟。原文件上限仍为 52,428,800 字节，原字节保存，所有新增引用均受数据库外键保护。

分页列表统一 page_size=10，触底追加，不再显示页码或加载更多按钮；下拉刷新重新读取首页。成员、分类和本机草稿本身为非分页集合，筛选器读取完整集合。

## 13. 随机点菜与家庭看板

随机点菜输入 1—50 的整数，从当前上架且分类启用的菜中随机选取，每组不重复；可反复换组，不创建菜单。可点菜不足时明确提示减少数量，不静默减少。确认将当前展示组追加到当前成员的独立草稿，合计最多 50 条；再经普通批次确认、提交、待认领、做菜、完成、评价与历史流程。随机刷新和生成本身不提交任何菜单意图，已有结果待确认时先去核对原批次。

数据看板按全部家庭记录统计记录天数、待做、正在做、完成、取消、启用成员、上架菜数、投票轮次、有效评价数和均分；热门菜与掌勺贡献各显示前 10，日期趋势显示最近 10 个存在有效点菜的日期。热门菜和趋势不计取消条目，掌勺贡献只计 completed，均分只计有效每日评价，空评价显示未评价。
