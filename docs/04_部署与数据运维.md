# 部署与数据运维

## 交付范围

唯一生产目标为 Linux amd64、Docker Compose 单应用容器、单进程。当前提供 [Compose 模板](../deploy/compose.yaml) 与 [维护实施契约](../deploy/backup-policy.json)，尚未提供经过目标主机验收的生产镜像和备份、恢复、媒体清理命令。模板不能直接充当已可用的生产安装器。

现有 HTTP/SQLite 开发实现可通过根目录 `Dockerfile` 与 [开发 Compose](../deploy/compose.dev.yaml) 构建，操作见 [中文教程](DOCKER.zh-CN.md) / [English tutorial](DOCKER.en.md)。开发容器使用独立命名卷、非 root、只读根文件系统和默认本机端口绑定，不安装维护任务，不作为生产模板的配套镜像。

生产门槛为 Node.js 24 / TypeScript / Fastify，镜像内实际 SQLite >= 3.51.3。开发 HTTP 实现的环境变量与生产模板不能混用；开发数据目录由 `FAMILY_DATA_ROOT` 指定，生产模板约定容器 `DATA_ROOT=/data`，须由正式实现落实并验收。

## 接入与存储

开发 Compose 的 `ALLOWED_HOSTS` 随 `DIANCAI_BIND_IP:DIANCAI_PORT` 设置，生产模板按 `HOST_LAN_IP:HOST_PORT` 约定，必须由正式实现落实。`ALLOWED_ORIGINS` 默认空；原生无 Origin 请求可用，确需浏览器联调时显式填写逗号分隔的完整来源。Host 白名单必须使用外部访问端口，不是固定容器端口；只有本机健康探针可以使用回环地址与容器监听端口。直接运行 Node 时通过 `ALLOWED_HOSTS` 指定实际 LAN 地址与端口，否则仅接受本机 Host。网络绑定、Host 检查和来源网络隔离须分别验证。

只允许可信家庭局域网访问。成员 ID 不是认证凭据，不得暴露公网。现场填写 `APP_IMAGE`、`HOST_LAN_IP` 和 `DATA_ROOT`；记录镜像 digest、操作系统、磁盘路径、UID/GID 和设备信息。模板不提供虚构的默认镜像或真实地址。

Compose 使用已有本机数据目录的 bind mount、非 root 用户、只读根文件系统、移除 capabilities 和受限日志。SQLite 不放在网络共享盘。时区显式固定为 `Asia/Shanghai`，容器与业务配置都必须一致。

## 停服备份

每日北京时间 04:00 发起排他停服全量备份，自动启动窗口为 04:00 至 04:15 前，不随机延迟、不补跑错过的任务。获取宿主维护锁，锁忙跳过；自动执行要求服务原本运行，并在停服前再次核对窗口。确认没有写入者后使用 SQLite backup API 生成快照，同时纳入全部被引用原媒体。

归档为不压缩 tar，清单采用 SHA-256 校验，验证后原子发布。只在新包有效且服务恢复后保留最近 10 份成功包；部分包不计数，失败时不清理已有成功包。服务恢复与归档结果分别记录，只在数据安全时恢复由本次维护停止的服务。错过运行须记录原因，手动重跑需明确停服授权。

每周至少一次复制到不同物理介质，验证全部清单哈希并记录复制与验证结果；异介质副本不自动清理。

## 恢复与媒体维护

恢复、覆盖、清理和停服必须获得明确授权。恢复在排他维护中同时处理数据库与被引用媒体，验证完整性并产生新数据代次。客户端检测代次改变后不能自动重送旧意图。

媒体原字节保存，单文件上限为 52,428,800 字节。识别、预览和下载分别处理，所有引用受保护；只能在排他停服维护中清理无引用媒体，不能在线附带执行垃圾清理。

## 验收记录

正式交付需记录实际运行库版本、镜像 digest、挂载与权限、局域网绑定、启动健康检查、备份失败与恢复演练、异介质验证和微信真机接入。静态测试不代表已部署 Docker、安装定时任务或执行真实备份，完整标准见 [开发与验收](05_开发与验收.md)。
