# 配置与决策

本文件汇总项目当前已明确的配置，约束来源为根目录协作规则、产品规则和可执行配置。具体业务语义见 [产品规则](01_产品规则.md)，运维参数见 [备份策略](../deploy/backup-policy.json)。

| 项目 | 明确决定 |
|---|---|
| 家庭范围 | 单家庭、可信家庭局域网，禁止暴露公网；成员选择不是认证 |
| 客户端 | 原生微信小程序，iOS 与 Android 使用同一业务设计 |
| 生产平台 | Linux `linux/amd64`，Docker Compose 单应用容器、单进程 |
| 数据存储 | SQLite 本机文件与原文件媒体，不使用网络共享数据库 |
| 生产技术门槛 | Node.js 24 / TypeScript / Fastify，镜像内 SQLite >= 3.51.3；当前 Node 内置 HTTP 开发实现不替代生产验收 |
| 业务时区 | 固定 `Asia/Shanghai`，北京时间 00:00 为业务日界线，审计时间为 UTC |
| 每日备份 | 每日北京时间 04:00 排他停服全量备份，自动启动窗口 04:00—04:15，不在白天自动补跑 |
| 本地保留 | 最近 10 份成功包；新包校验且服务恢复后才清理超额旧包，失败不清理 |
| 独立副本 | 每周至少一次异介质副本，逐项校验清单哈希并记录结果 |
| 媒体 | 单文件最多 52,428,800 字节，保存原字节；清理仅限排他停服维护 |
| 恢复 | 同时恢复数据库与被引用媒体，生成新数据代次，不自动重送旧客户端意图 |

## 现场配置

现场 IP、镜像 tag/digest、数据根目录、UID/GID、主机与手机信息必须使用真实值记录，不以示例代替。模板为 [deploy/.env.example](../deploy/.env.example)。私人配置、家庭数据与备份不得提交到公共仓库。

## 验收边界

开发实现、本地测试、原型演示与生产验收分别记录。生产镜像、备份/恢复/媒体清理命令、目标 Linux 安装和微信正式发布证据尚需落实，见 [开发与验收](05_开发与验收.md)。不建设 Windows 服务、网页运维台、数据库热切换、Redis、消息队列、微服务或多租户。

现有开发 HTTP 实现另有同一 Linux amd64 路线的 Docker 构建入口 `Dockerfile` / `deploy/compose.dev.yaml`，使用开发命名卷，默认仅绑定本机地址；它不是生产模板的配套镜像，不改变正式技术门槛和维护规则。操作见 [中文教程](DOCKER.zh-CN.md) / [English tutorial](DOCKER.en.md)。
