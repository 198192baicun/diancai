# 系统与数据设计

单家庭、可信家庭局域网 Linux amd64、单应用单进程、本机 SQLite 与原文件媒体。开发 HTTP 实现使用 Node 内置 HTTP 与 node:sqlite；正式目标门槛与设备验收以 README 和开发验收文档为准。

## 数据结构

有序迁移文件是结构的可执行来源。001 建立家庭、成员、分类、菜品、步骤、菜单、评价、投票、媒体与回执；002 建立每日评价唯一性和不可修改保护、多选投票；003 加入头像、介绍语音、事项备注/认领/完成语音、完成文字、评价语音、投票停止收票时间、菜单完成照片与投票成员备注。

menu_completion_photo 按事项与位置唯一，每事项最多9张，引用已完成事项和媒体。vote_member_note 按轮次与成员唯一，保留投票提交时成员姓名、200字备注、可选语音和更新时间；迁移旧票以迁移时现存名称填充。所有媒体字段通过外键引用 media，无级联删除业务历史。未引用媒体仅排他停服维护清理。

menu_item 继续使用 pending/cooking/completed/cancelled 四状态。完成照片、语音与完成操作同事务保存，评价语音与评价首次 INSERT 同事务保存，保留 review_immutable 触发器。公共菜品图文语音使用 revision 校验，历史事项快照不随公共编辑改变。

投票仍最多一轮 active，增加 voting_closed_at 区分尚可收票与并列待裁决。最后一票和成员启停事务检查当前启用成员是否全部至少选一道。收齐后冻结票数，唯一最高结束，并列保留 active 直到发起人裁决。触发器阻止停收后的 ballot 插入、更新与删除。停收后不随成员变化重开。

## 事务与请求

HTTP 入口按接口契约检查 Host 与 Origin，包括媒体和 OPTIONS；空配置默认只允许本机 Host，不允许任何携带 Origin 的来源。Compose 将发布地址和宿主端口作为业务 Host，仅本机健康 GET 使用监听端口探针例外。媒体响应使用可处理异步错误与客户端断开的流管线；错误终止当前传输，不结束应用进程，不更改原文件或数据库引用。

BEGIN IMMEDIATE 串行化写操作；上下文、成员启用、状态和 revision 在写事务内检查。批次载荷包含可选备注语音，原幂等 Key 与载荷冻结；回执与事项同事务写入，重放不重复创建。无语音的旧请求保持原散列语义。随机结果只读，不绕过正常草稿与批次。

文件 I/O 在业务事务外执行，完整原文件落盘后才登记引用。服务区分 image/* 与 audio/* 引用。图片识别与设备预览能力分离；语音不转码或转写。每文件52,428,800字节；导入单篇200MiB、最多50段。

小红书仅公开白名单 HTTPS 页面与配图，DNS结果经公网检查并固定连接地址，短缓存30秒。最多3张并发下载，按原顺序返回，任一失败不创建菜品。整体截止100秒，单连接25秒截止和15秒空闲超时。无登录、验证码或页面脚本执行。

## 查询与客户端

分页使用稳定排序位置及过滤条件签名游标，客户端 page_size=10 触底追加；新筛选与作用域变化使迟到响应失效。看板统计全历史，取消条目不参与有效进度和热门菜，评价按每日唯一有效记录聚合。

录音、草稿和上传归属当前成员/服务/实例/代次；切换后迟到回调不写入新作用域。客户端采用共享录音管理器避免重复监听；录音或上传期间阻止相关提交。媒体加载不阻塞主要文字。
