# Linux 部署与数据运维

遵守根目录约束。只维护 Linux amd64 Docker Compose 单应用路线；当前提供生产模板与流程设计，以及可构建的开发 HTTP 镜像。开发镜像不作为已通过生产验收的镜像，不声称备份命令已经实现。

读 `../docs/04_部署与数据运维.md` 和 `../docs/06_配置与决策.md`。镜像、LAN 地址和数据根须填写真实值。唯一平台为 `linux/amd64`，Compose 显式固定 `FAMILY_TIMEZONE` / `TZ` 为 `Asia/Shanghai`，不提供时区选择或多架构发布流水线。精确 tag/digest、非 root、只读根文件系统、持久挂载与日志保留必须验证。SQLite 本地盘，不使用网络共享数据文件。

发布端口绑定与源网络限制是两件事。不能仅凭 host_ip 或 UFW 配置推断访问隔离；检查真实 Docker/防火墙后端和非允许网络。healthcheck 不等于自动重启策略。

备份/恢复/发布/清理共享主机排他维护锁。停服确认没有写进程后处理数据库与媒体；安全包校验和整套候选数据交换遵照运维文档。不得提供直接覆盖现用库、跟随归档链接或边运行边删图片的快捷命令。

真实停服、恢复、清理或发布须明确授权。验证优先使用临时数据。设计模板的 YAML 解析不是 `docker compose config`、镜像启动或目标主机验收；分别报告执行层次。CPU、时区和备份方案已确定。按 `backup-policy.json` 实现每日 04:00 调度、04:00—04:15 自动启动保护、最近 10 份成功包和每周异介质副本；不得把策略文件说成已运行的备份程序。先记录原服务状态，备份归档和服务恢复分别记结果；自动任务不能擅自启动原已停服的应用。
